# 교사용 앱 디자인·작업 원칙 (Hagisiro 3주 작업에서 정리)

새 앱을 만들 때 이 문서를 맨 먼저 읽고, 사용자(담임 선생님·비개발자)가 반복해서 지적한 방식을 처음부터 적용한다.

## 1. 제품 철학
- **가볍고 빠릿빠릿함이 최우선.** 누르는 횟수·선택지를 줄인다. 같은 결과면 코드·연산이 적은 쪽, 계산된 위치보다 고정값. 최적화는 코드 정리가 아니라 구조를 의심하는 것(매번 다시 그리지 말고 재사용 등). 전후 숫자를 보여준다.
- **단순함.** 안내문·경고문·당연한 설명을 마음대로 넣지 않는다. 입력칸 안 placeholder도 특별한 경우만. 입력칸에 아이콘 없음.
- **토스트는 거의 쓰지 않는다**(저장 실패 같은 꼭 필요한 경우만). 대기는 글자("로그인 중…")가 아니라 만들어 둔 대기 애니메이션으로.
- **행동은 막지 말고 비활성화로 안내한다.** 안 되는 상태는 숨기거나 에러를 띄우지 말고 흐리게(비활성) 둔다. 상한에 닿으면 추가 버튼을 숨기지 않고 비활성. 빈 상태도 틀은 그대로 두고 흐리게(없음 글자만 덜렁 두지 않음). 비활성 컨트롤은 hover로 색·커서가 변하지 않는다.
- 삭제·변경은 목록을 직접 건드리기보다 편집 안에서만. 삭제 확인은 "○○를 삭제할까요?" 한 줄.

## 2. 일관성과 위계 (가장 중요한 대전제)
- 같은 기능 = 같은 단어·아이콘·애니메이션·색. 한 곳을 고치면 같은 유형을 전부 같이 고친다(말 안 해도). 비슷한 문제를 먼저 찾는다. 점검할 땐 모든 화면·팝업(학생 화면, 로그인 포함)을 본다.
- **칸·버튼·칩·팝업의 위치와 크기는 절대 변하지 않는다**(스크롤바 유무, 모드 전환, 상태줄 문구 변화에도). 버튼은 제자리. 레이아웃이 밀리면 버그다.
- 글자 크기는 큰 것에서 작은 것으로 단계적으로. 팝업 안쪽 여백 동일. 버튼 색·모양은 용도별로 통일. 스크롤바 굵기는 두 종류만.

## 3. 시각 규칙
- 팔레트 고정, 새 색은 반드시 물어본다(투명도 변형은 같은 색). 회색 글씨 = 편집 못 하는 것·비활성. 누를 수 있는 것은 회색이 아니다. 정보 표시에는 배경 채움 없음, 입력칸만 배경.
- 모서리는 크기 사다리(4·6·8·10·12px). 같은 계열 도형은 같은 반경.
- 아이콘: 단순한 선, 같은 굵기, 부품끼리 붙지 않음, 같은 의미 = 같은 모양, 시각적 면적으로 크기 균형. 삭제=빨간 휴지통, X는 닫기/지우기 전용, 화살표는 쉐브론, 뒤로=←.
- 버튼: 대부분 테두리 없음. 주 버튼(저장·확인·만들기)은 글자만. 툴팁은 아이콘만 있는 버튼에만. hover 확대·클릭 축소 없음.
- 애니메이션: 같은 상황 = 같은 효과·시간. 투명도 설정은 전환 중에도 유지. 사용자가 보기에 "날카로운" 전환은 부드럽게.

## 4. 문구
- 한국어. 앱 안은 해요체·짧게, 소개 글은 사무적 합니다체. 버튼은 한자어 명사형(삭제·초기화·이동·편집·확인·저장). 구어체·간지러운 말투·과장 금지. 조사는 받침에 맞춰 자동. 날짜 "11.23. (월)", 범위 "11.23. (월) ~ 11.27. (금)". 가운뎃점=그리고, 슬래시=또는. 설명 문장은 마침표로 끝낸다.
- 영어 표기·브랜드는 한 가지로 통일(앱 이름 대소문자 포함).

## 5. 소개 페이지
- 소제목은 명사형, 본문은 합니다체. 데모는 핵심 입력만 크게(확대) 보여주고, 데모 안에 설명 문구를 넣지 않는다. 데모는 실제 앱의 컨트롤을 그대로 흉내 낸다. 같은 종류 카드는 같은 크기·같은 모서리 비율. 예시 이름은 우리말(김네모·박동글 등).
- 그림은 앱 모양이 바뀔 때마다 다시 찍는다.

## 6. 일하는 방식 (사용자가 원하는 협업)
- 맥락상 뻔하면 지시를 기다리지 말고 바로 실행하고 짧게 반말로 보고한다. 애매한 것만 묻는다. 요청하지 않은 것은 바꾸지 않는다. 디자인 선택(아이콘 모양·간격·크기)은 사용자 몫이라 비교 샘플을 보여주고 고르게 한다.
- 확인하지 못한 것은 숨기지 말고 말한다. 직접 테스트(PC·모바일 폭 스크린샷)하고 나서 보고한다. 사용자는 배포 후 버그를 발견하고 싶어 하지 않는다.
- 사용자는 개발자가 아니다. 쉬운 말로. 이전 대화에서 말한 것을 다시 묻거나 부정하지 않는다(대화 기록·메모리·인수인계 문서를 먼저 찾는다).
- 커밋마다 바로 push(한국어 커밋 메시지).
