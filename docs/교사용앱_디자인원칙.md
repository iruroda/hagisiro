# 교사용 앱 디자인·작업 원칙 (Hagisiro 3주 작업 전체를 중요도 순으로 정리)

새 앱을 시작할 때 맨 먼저 읽는다. 순서가 곧 중요도다. 위쪽 항목은 사용자가 가장 여러 번, 가장 강하게 요구했거나, 어겼을 때 가장 크게 화낸 것이다.

## A. 앱의 존재 이유 (어기면 앱 자체를 다시 만들어야 하는 수준)
1. **가볍고 빠릿빠릿함이 최우선.** 남의 앱 대신 직접 만드는 이유다. 누르는 횟수·선택지를 줄이고, 같은 결과면 코드·연산이 적은 쪽, 계산된 위치보다 고정값을 쓴다. 최적화는 코드 정리가 아니라 **구조를 의심하는 것**이다(예: 달력 칸을 렌더링마다 새로 만들고 재측정하는 구조를 사용자가 시키기 전에 먼저 찾아냈어야 했다). 수치(전후 비교)로 보여준다. 3번 이상 반복될 법한 것은 처음부터 묻지 않고 줄인다.
2. **일관성과 위계.** 같은 기능 = 같은 단어·아이콘·애니메이션·색·모양. 한 곳을 고치면 **같은 유형을 앱 전체에서 같이** 고친다(시키지 않아도). 형제 문제는 사용자가 말하기 전에 먼저 찾는다. 점검은 모든 화면·팝업(학생 화면·로그인 포함)을 대상으로 한다. 비슷한 상황은 같은 효과·같은 시간.
3. **위치와 크기는 절대 변하지 않는다.** 칸·버튼·칩·팝업이 스크롤바 유무, 모드 전환, 상태 문구 변화, 로딩에 따라 밀리거나 커지면 버그다. 버튼은 항상 제자리.
4. **단순함.**
   - 안내문·경고문·당연한 설명을 마음대로 넣지 않는다. 입력칸 placeholder, 입력칸 안 아이콘 없음.
   - **토스트는 거의 쓰지 않는다**(저장 실패 정도). 기다리는 상태는 글자("로그인 중…")나 토스트가 아니라 만들어 둔 대기 애니메이션으로.
   - **행동은 막지 말고 비활성화로 안내한다.** 안 되는 건 숨기거나 에러로 말하지 말고 흐리게 둔다. 상한에 닿으면 추가 버튼은 숨기지 않고 비활성. 빈 상태는 "없음" 글자만 두지 않고 **틀을 그대로 두고 흐리게**. 비활성은 hover에도 색·커서가 안 변한다.
   - 부가 기능·아이콘은 안내하지 않고 눌러보며 알게 둔다. 툴팁은 아이콘만 있는 버튼에만(글자·칸에는 없음).
5. **주객을 뒤집지 않는다.** 주인공(앱 화면)은 중심·가장 크게, 장식(바탕화면 아이콘 등)이 양보한다. 어떤 요소를 위해 핵심을 옮기거나 줄이지 않는다.

## B. 사용자가 반복해서 화낸 협업 방식 (이 앱 작업 중 실제로 반복된 실수)
1. **맥락상 뻔하면 지시를 기다리지 않는다.** "줄이라는 뜻이었잖아" 같은 상황을 여러 번 만들었다. 바로 하고 짧게 반말로 보고한다.
2. **과거 대화를 다시 묻거나 부정하지 않는다.** 사용자가 이미 말한 것(레이아웃, 용어, 결정)을 "없었다"고 단정하지 말고 기록(대화·메모리·인수인계 문서)을 먼저 확인한다. 압축 뒤엔 반드시 저장된 문서부터 다시 읽는다.
3. **한 번에 제대로.** 부분만 고치고 다시 지적받게 하지 않는다(같은 유형 전체 수정, 모바일·PC 폭 모두 확인, 되돌릴 일 최소화). "끝이 안 난다"가 가장 큰 짜증 원인이다.
4. **직접 테스트하고 나서 보고하고, 확인 못 한 것은 그대로 말한다.** 사용자는 쓰다가 버그를 발견하고 싶어 하지 않는다("완벽한 모델로 배포"). "폰이 없어서 못 한다"로 건너뛰지 말고 가능한 모든 방법으로 시도한다.
5. **요청하지 않은 것은 바꾸지 않는다.** 애매하면 짧게 확인(한 번은 삭제를 반대로 한 사고). 단, 뻔한 수정은 묻지 않고 한다. 반대하지 않은 제안은 승인된 것으로 본다.
6. **디자인 선택은 사용자 몫.** 아이콘 모양·간격·크기·새 색은 비교 샘플을 나란히 보여주고 고르게 한다. 진짜 열린 선택에만.
7. 사용자는 개발자가 아니다. 쉬운 말로, 짧게. 입에 발린 말·장식적인 사과를 하지 않는다.
8. 파일은 GitHub·클라우드 문서에 저장하고 사용자 PC에 새 파일을 만들지 않는다. 커밋마다 바로 push.

## C. 시각·인터랙션 규칙
- **색**: 팔레트 고정(보라+청록 계열), 새 색은 물어본다(투명도 변형은 같은 색). 회색 글씨 = 편집 못 하는 것·비활성, 누를 수 있는 것은 회색이 아님. 정보 표시는 배경 없음, 입력칸만 배경. 토요일 파랑·일요일/공휴일 빨강.
- **모서리**: 크기 사다리(4·6·8·10·12px), 같은 계열은 같은 반경.
- **아이콘**: 단순한 선·같은 굵기·부품끼리 안 붙음·같은 의미 = 같은 모양·시각 면적으로 크기 균형. 삭제=빨간 휴지통, X는 닫기/지우기 전용, 화살표는 쉐브론, 뒤로=←.
- **버튼**: 대부분 테두리 없음, 주 버튼은 글자만, 같은 기능 = 같은 단어, 한자어 명사형(삭제·초기화·이동·편집·확인·저장). hover 확대·클릭 축소 없음. 드롭다운은 앱 고유 스타일(네이티브 금지)·고정 폭. 항목 삭제는 편집 안에서만.
- **팝업**: 제목·아이콘 = 연 버튼의 이름·아이콘. 단순 확인창은 제목 없음, 삭제 확인은 "○○를 삭제할까요?" 한 줄. 안쪽 여백 동일. 팝업이 본창에 영향을 주지 않음. 즉시 저장 팝업엔 닫기 버튼 없음.
- **애니메이션**: 같은 상황 = 같은 효과·시간. 투명도 설정은 전환 중에도 유지. 날카로운 전환은 부드럽게. 스크롤바 굵기는 두 종류만.
- **창**: 창은 화면 밖으로 못 나가고(듀얼 모니터 포함), 변경 모드는 바깥 클릭으로 끝난다.
- **모바일**: 700px 이하 폰은 하단 탭·날짜 탭 시 입력 시트, 태블릿은 PC와 같게.

## D. 문구
- 앱 안은 해요체·짧게, 한국어. 조사는 받침에 맞춰 자동. 날짜 "11.23. (월)", 범위 "11.23. (월) ~ 11.27. (금)", 가운뎃점=그리고, 슬래시=또는. 설명 문장은 마침표로 끝.
- 구어체·간지러운 말투·과장 금지. 브랜드·외래어 표기는 한 가지(앱 이름 대소문자, "Google", "Windows", "캘린더").

## E. 소개 페이지 (사용자가 직접 고친 방향)
- 소제목 명사형, 본문 합니다체, 짧게 교사가 하는 일만. 만든 사람·설치 방법·자잘한 기능은 쓰지 않는다.
- 데모는 핵심 입력만 크게, **데모 안에 설명 문구 없음**, 실제 앱의 컨트롤을 그대로 흉내 내고 실제 동작과 같게(상태줄이 입력 중 변하고 엔터에서 표가 채워짐). 같은 종류 카드는 같은 크기·같은 모서리 비율. 예시 이름은 우리말.
- 앱 모양이 바뀌면 그림을 다시 찍는다.
